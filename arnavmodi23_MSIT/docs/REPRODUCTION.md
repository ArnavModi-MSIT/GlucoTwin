# Setup and model preparation

Run commands from `arnavmodi23_MSIT/` with Python 3.10 and the pinned requirements.
Datasets, generated patient manifests and trusted model binaries stay local.
The launcher does not download data or train missing models.

For a first run, install `requirements.txt` and launch the dashboard. The built-in
**Synthetic demo** requires no patient files or saved models. It is a fictional
workflow demonstration with a deterministic trend rule, not a benchmark or a
substitute for the research model. The instructions below enable research cohorts.

## Evaluation walkthrough

1. Use the synthetic worked example to inspect the interface immediately.
2. Prepare the CGMacros numerical and event models with the commands below.
   This is the primary demonstration of linked historical profile, CGM and
   heart-rate inputs and advance high-glucose onset prediction.
3. Launch the dashboard and select **CGMacros**, then a development patient.
   Review the profile, model-input explanation and separate event research panel.
4. Advance replay in five-minute steps. Issued forecasts and event scores remain
   fixed; outcomes appear only after their specified availability time. A score
   is an uncalibrated model output, and a research flag is not a clinical alert.
5. Compare the revealed outcomes with persistence and inspect the aggregate
   [development results](RESULTS.md). A single patient session does not reproduce
   population-level performance. Reserved-test patients stay excluded.

RBG preparation is optional for this walkthrough. It enables the separate type 1
diabetes numerical benchmark; its results are not pooled with CGMacros.

## CGMacros numerical model

```powershell
python download_cgmacros.py
python scripts/audit_cgmacros.py
python scripts/check_cgmacros_interpolation.py
python scripts/freeze_cgmacros_contract.py
python scripts/prepare_features.py
python scripts/train_baselines.py
```

Use the [CGMacros source release](https://physionet.org/content/cgmacros/1.0.0/)
and follow its CC BY-NC-SA 4.0 terms. The downloader retrieves CSV members and
skips photographs. Source checks and the split generator establish the fixed
replay contract before training. See the [data contract](../DATA_CONTRACT.md).

## RBG numerical models

Obtain `Demographics.csv` and `5_min_sampling.zip` from
[DiaData v3](https://zenodo.org/records/17285631). Extract the `raw.zip` member to
`data/5_min_sampling/raw.zip` and place the original demographic CSV at
`data/raw/diadata/Demographics.csv`. Keep the original bytes for hash checks.

```powershell
python scripts/import_rbg.py --archive data/5_min_sampling/raw.zip --demographics data/raw/diadata/Demographics.csv
python scripts/freeze_rbg_contract.py
python scripts/prepare_rbg.py
python scripts/train_rbg_baselines.py
python scripts/prepare_rbg_replay.py
```

The importer streams the source archive rather than expanding the full CSV.
Allow space for the archives, approximately 1.4 GB RBG subset and processed
matrices. A different source subset or frozen split causes an error. Training
uses training patients only; reserved-test targets are not prepared. Dataset
terms are CC BY-NC 4.0 with applicable original-source attribution.

## CGMacros event model

After preparing CGMacros, install the pinned optional dependency and reproduce
the active event protocol on CPU:

```powershell
python -m pip install -r requirements-event.txt
python scripts/run_event_study.py --device cpu
```

This creates the private input/role manifests and saved fold models, plus the
aggregate `reports/event_study_gpu_v2.json` required for runtime verification.
The protocol filename is retained to match existing artifact fingerprints;
it does not imply GPU execution. Do not modify cutoffs against reserved data.
See [event replay](EVENT_REPLAY.md) and [current results](RESULTS.md).

The separate [independent tuning comparison](EVENT_COMPARISON.md) gives both
feature arms the same candidate budget and preserves the active v2 models.
Its versioned outputs are separate from the files loaded by the dashboard.

## Launch

Run `python scripts/launch_dashboard.py`, or double-click `StartGlucoTwin.cmd`
at the repository root. The local dashboard opens at `http://127.0.0.1:8000`.
Use `--port 8001` for another port or `--no-browser` for manual opening.
Press Ctrl+C in the server window to stop it. Install only trusted models
generated by these scripts; joblib files from other sources can execute code.

Model loading verifies SHA-256 before deserializing the checked bytes. The
published `configs/replay_artifact_hashes.json` identifies the current trusted
checkpoint. Fresh training writes a private `artifacts/replay_hashes.json` with
fingerprints of its own outputs. An unregistered or changed model is rejected.
These manifests must also be trusted; hashes do not establish a model's origin.
Research loading enforces the pinned numerical runtime and rejects serialized
scikit-learn version mismatches. New RBG artifacts also record that version
explicitly; existing checkpoint bytes have been preserved.

The launcher warns on installed-version differences so the fictional demo can
still be tried. This does not certify an untested environment. Research cohorts
remain unavailable until their pinned dependency and artifact checks pass.

## Current application checks

```powershell
python scripts/run_tests.py
```

The included tests cover active feature preparation, model contracts, replay
timing, event outcomes, launcher behavior and the API. Synthetic checks require
no dataset. Node.js 22+ is required for the JavaScript checks; use `--node PATH`
if necessary. Add `--integration` to include prepared local saved-event and API
checks. The runner also honors `GLUCOTWIN_INTEGRATION=1`. CI uses the same runner
on Python 3.10/3.12 and installs the pinned optional event dependency to exercise
the small CPU XGBoost serialization check. A separate synthetic fixture fits a
numerical model, saves/loads it, and serves delayed HTTP replay outcomes.
These checks establish implementation behavior,
not clinical reliability or a new clean-machine training result.

Optional exploratory ranges: after preparing the active artifacts, run `python scripts/prepare_intervals.py`. See [uncertainty methods and limitations](UNCERTAINTY.md). Restart the server after calibration; existing sessions keep their issued bounds fixed.
